# WB Монитор цен

Следит за ценами выбранных товаров на Wildberries и оповещает, когда цена упала
или достигла целевой.

Отслеживается **итоговая сумма — товар плюс доставка**, то есть ровно та цифра,
которую показывает приложение.

## Файлы

| Файл | Назначение |
|---|---|
| `WBМонитор.ps1` | Сам скрипт |
| `Товары.txt` | Список артикулов: `артикул ; целевая цена ; заметка` |
| `Проверить.bat` | Ручной запуск двойным щелчком |
| `Настроить-Телеграм.ps1` | Разовая настройка Telegram-бота |
| `Настроить-Телеграм.bat` | Запуск настройки двойным щелчком |
| `История.csv` | Копится автоматически: только строки, где сумма изменилась |
| `Оповещения.log` | Хронология всех событий |

## Как работает

1. Читает `Товары.txt`.
2. Одним запросом (порциями по 50 артикулов) получает данные с
   `card.wb.ru/cards/v4/detail` — это тот же открытый эндпоинт, которым
   пользуется сайт WB. Ключи и авторизация не нужны.
3. Считает итог: `price.product` + `price.logistics`.
4. Сравнивает с последней записью по этому артикулу в `История.csv`.
5. Если сумма снизилась — пишет в лог и показывает всплывающее уведомление Windows.
   В сообщении указано, **что именно** подешевело: сам товар или только доставка.
   Если снижение дошло до целевой цены — отдельная строка «ДОСТИГНУТА ЦЕЛЬ».
6. В `История.csv` дописывается строка **только при изменении суммы**, поэтому
   файл остаётся компактным и читается как история скидок. Хранятся и составляющие
   (`Цена`, `Доставка`, `ЦенаБазовая`) — итог всегда можно пересобрать заново.

## Запуск

Разово:

```bat
Проверить.bat
```

Или с параметрами:

```powershell
powershell -ExecutionPolicy Bypass -File WBМонитор.ps1 -Валюта rub -КодРегиона -1257786
```

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `-Валюта` | `kzt` | `kzt`, `rub`, `byn`, `uzs`, `kgs`, `amd`, `usd` |
| `-КодРегиона` | `269` (Актобе) | параметр `dest` в API WB |
| `-УчитыватьДоставку` | `$true` | как в приложении. `$false` — только цена товара |
| `-СкидкаКошелькаПроцент` | `0` | если WB Кошелёк даёт скидку на товар, % |
| `-БезВсплывающихОкон` | — | не показывать всплывашку Windows. **В Telegram сообщение всё равно уходит** — именно так работает фоновый запуск |

### Коды регионов (dest)

| Регион | dest |
|---|---|
| Актобе | `269` |
| Алматы | `234` |
| Астана | `84` |
| Караганда | `134` |
| Шымкент | `230` |
| Атырау | `123587641` |
| Ташкент | `495` (валюта `uzs`) |
| Москва | `-1257786` (валюта `rub`) |

Код своего города можно узнать так (подставить координаты):

```powershell
Invoke-RestMethod "https://user-geo-data.wildberries.ru/get-geo-info?latitude=50.2839&longitude=57.1670"
```

В ответе поле `xinfo` содержит готовую строку `curr=...&dest=...`.

### Про привязку к аккаунту

Привязка не нужна — проверено:

- **Персональных скидок в ответе нет.** Параметр `spp` (скидка постоянного
  покупателя) сервер игнорирует: при `spp` от 0 до 99 цена не меняется. WB давно
  вшил СПП в саму карточку.
- **Цена товара одинакова во всех городах Казахстана** — 474 220 ₸ и в Алматы,
  и в Астане, и в Актобе. Регион меняет только доставку.
- **Расхождение с приложением объясняется доставкой.** Приложение показывало
  486 660 ₸ = 474 220 (товар) + 12 440 (доставка в Актобе). Совпадение точное,
  до тиына, на обоих товарах.

Поэтому скрипт считает итог сам и авторизация ему не требуется. Если у тебя
всё же появится скидка WB Кошелька на товар — задай её процент в
`-СкидкаКошелькаПроцент`, она применится к товару, но не к доставке.

## Уведомления в Telegram

Настраивается один раз:

1. В Telegram написать [@BotFather](https://t.me/BotFather), команда `/newbot`,
   получить токен вида `1234567890:AAH...`.
2. Запустить `Настроить-Телеграм.bat`. Скрипт спросит токен, проверит его через
   `getMe`, попросит нажать `/start` в чате с ботом, сам найдет `chat_id`
   через `getUpdates` и отправит тестовое сообщение.
3. Токен сохраняется в `%USERPROFILE%\.claude\wb_telegram.xml`, зашифрованным
   **DPAPI** — файл читается только из-под твоей учетной записи Windows.
   Это та же схема, что у токенов Jira и Confluence.

Пока настройка не сделана, монитор работает как обычно — Telegram просто
пропускается, ошибок нет.

Уведомления приходят **и при снижении, и при росте** — всплывающим окном Windows
и в Telegram одновременно. Сообщение выглядит так:

```
📉 TROUVER Робот-пылесос S70 Ultra Roller
512 440 -> 486 660 тг  (-25 780, -5.0%)
изменилась цена товара
🎯 цель 430 000 достигнута
https://www.wildberries.ru/catalog/1422010347/detail.aspx
```

Чтобы слать в группу, а не в личку: добавить бота в группу и написать там `/start`
(у ботов по умолчанию включен режим приватности, обычные сообщения они не видят).

## Команды боту

Списком товаров можно управлять прямо из Telegram:

| Команда | Что делает |
|---|---|
| `/list` | что отслеживается — артикул и ссылка на карточку |
| `/price` | названия и цены прямо сейчас |
| `/add 1422010347` | добавить артикул |
| `/remove 1422010347` | убрать из отслеживания |
| `/help` | подсказка |

Русские варианты тоже работают: `/список`, `/цена`, `/добавить`, `/удалить`, `/помощь`.

Названия товаров в сообщениях — кликабельные ссылки на карточку WB. Разметка
отправляется как HTML; если Telegram её отвергнет (например, в названии попадётся
неожиданный символ), сообщение уйдёт повторно простым текстом, с адресом
отдельной строкой. Потерять уведомление из-за разметки нельзя.

### Целевая цена

Не обязательна, среднее поле в `Товары.txt` можно оставить пустым. Если нужна —
впиши число или добавь его вторым аргументом: `/add 1422010347 430000`. Тогда в
уведомлении появится отметка, когда итоговая сумма опустится до этого значения.

**Ответ приходит не мгновенно.** Бот не работает сам по себе — команды забирает
очередной прогон, поэтому задержка до 10 минут. Срочно — нажми **Run workflow**
на вкладке Actions, прогон стартует сразу.

**Команды принимаются только из твоего чата.** `chat_id` сверяется с секретом
`WB_TELEGRAM_CHAT`, сообщения из любых других чатов отбрасываются с записью в лог.
Иначе любой, кто найдёт бота по имени, смог бы менять твой список.

Изменения `Товары.txt` коммитятся в репозиторий, так что в git видно, когда и что
добавлялось. Указатель прочитанных сообщений хранится в `ОчередьТелеграм.txt` —
без него Telegram отдавал бы одни и те же команды снова и снова.

### Меню команд в Telegram

Чтобы команды подсказывались при вводе, отправь @BotFather `/setcommands`,
выбери бота и вставь:

```
list - что отслеживается
price - цены прямо сейчас
add - добавить артикул: /add 1422010347 430000
remove - убрать артикул: /remove 1422010347
help - подсказка
```

## Нагрузка на WB и лимиты

- За один прогон уходит **один HTTP-запрос** — все артикулы передаются списком
  `nm=a;b;c`, до 50 штук в запросе. Два товара или двадцать — разницы нет.
- При 429 («слишком часто») скрипт ждет и повторяет: паузы 5, 15, 45 секунд,
  до 4 попыток. Одиночный сбой сети монитор не роняет.
- Эндпоинт `card.wb.ru` к частоте спокоен: больше двадцати запросов подряд без
  пауз прошли без единого 429. А вот `search.wb.ru` отдает 429 сразу — поэтому
  поиск по названию не используется.

## Запуск в GitHub Actions (работает без твоего компьютера)

Telegram-бот сам ничего не проверяет — он только доставляет сообщения. Опрашивать
WB должна программа, и она обязана где-то выполняться. GitHub Actions даёт для
этого бесплатный раннер по расписанию.

Проверено: `card.wb.ru` отвечает с датацентрового IP за пределами Казахстана
теми же числами (474 220 + 12 440 при `dest=269&curr=kzt`). Гео-блокировки нет,
регион задаётся параметром запроса, а не адресом звонящего.

### Что нужно сделать

1. Создать на GitHub **приватный** репозиторий.
2. Выложить туда содержимое этой папки:

   ```bash
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```

3. Завести два секрета: **Settings → Secrets and variables → Actions →
   New repository secret**

   | Имя | Значение |
   |---|---|
   | `WB_TELEGRAM_TOKEN` | токен от @BotFather |
   | `WB_TELEGRAM_CHAT` | `chat_id`, его печатает `Настроить-Телеграм.ps1` |

4. Проверить, что у задачи есть право на запись: **Settings → Actions → General →
   Workflow permissions → Read and write permissions**. Без него шаг «Сохранить
   историю» не сможет закоммитить `История.csv`.
5. Открыть вкладку **Actions → WB Монитор цен → Run workflow** и убедиться,
   что прогон зелёный.

### Как это устроено

Раз в час раннер забирает репозиторий, выполняет тот же `WBМонитор.ps1` под `pwsh`
(на ubuntu-раннерах PowerShell 7 предустановлен) и коммитит обновлённую
`История.csv` обратно. Токен берётся из переменных окружения — DPAPI на чужой
машине не работает, поэтому в скрипте два источника настроек: переменные
окружения в приоритете, локальный зашифрованный файл как запасной.

### О чём стоит знать заранее

- **Расписание неточное.** Минимальный интервал cron — 5 минут, но GitHub
  регулярно задерживает запуски на 10–15 минут и изредка пропускает. Для ловли
  скидок это неважно.
- **Бесплатных минут хватает.** Приватный репозиторий даёт 2000 минут в месяц,
  прогон занимает меньше минуты, ежечасно выходит ~744.
- **Расписание отключается после 60 дней без активности в репозитории.**
  Поэтому каждый прогон обновляет `ПоследняяПроверка.txt` и коммитит его — это
  и отметка живости, и активность. Если GitHub всё же отключит задачу, он пришлёт
  письмо, включается обратно одной кнопкой.
- **Не запускай локально и в облаке одновременно.** `История.csv` — общее
  состояние, разойдётся и даст конфликт при `git push`. Перед локальным прогоном
  делай `git pull`.

## Автозапуск по расписанию на своём компьютере

Создать задачу в планировщике Windows (раз в час):

```powershell
$Действие = New-ScheduledTaskAction -Execute "powershell.exe" -Argument '-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File "C:\Users\y.kochetov\Documents\00_Tools\01_Claude\01_Projects\!_Утилиты\WBМонитор\WBМонитор.ps1"'
$Триггер = New-ScheduledTaskTrigger -Once -At (Get-Date) -RepetitionInterval (New-TimeSpan -Hours 1)
Register-ScheduledTask -TaskName "WB Монитор цен" -Action $Действие -Trigger $Триггер -Description "Проверка цен Wildberries"
```

Удалить:

```powershell
Unregister-ScheduledTask -TaskName "WB Монитор цен" -Confirm:$false
```

## Ограничения

- Эндпоинт неофициальный: WB может поменять версию пути (`v4` → `v5`) или
  структуру ответа. Тогда в логе появится «WB не вернул ни одного товара»
  или ошибка запроса — путь правится в функции `Получить-ДанныеWB`.
- Поисковый эндпоинт `search.wb.ru` с корпоративной сети отдаёт 429 — поэтому
  поиск по названию не используется, только точные артикулы.
